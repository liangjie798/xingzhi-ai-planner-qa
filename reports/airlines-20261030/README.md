## 接入前必须解决的问题

- **数值**：天津航空售罄舱位出现`Infinity`，只接受有限正数，并检查该舱位可售状态。
- **口径**：区分裸票价、含税总价、会员优惠与推广日历。吉祥首页302元，进入结果为320元；不能沿用首页价。
- **承运人**：保留营销航班号、实际承运人、经停/中转、跨日信息。重庆官网展示CZ/OQ双号；厦航共享航班由东航承运。
- **条件一致**：结果必须与出发地、目的地、日期、乘客一致；瑞丽脚本从目标无锡错选到芒市的结果已经拒收。
- **失败分型**：需登录、需人工验证、会话过期、TLS错误、无数据、解析失败分别返回；城市编码不明确时不能返回“无航班”。
- **稳定性**：每站专用适配、低并发、超时、缓存、熔断和来源时间；需在实际部署环境重复验证。一次本机成功不等于长期服务可用。
- **权限**：国航按已核对的协议限制不执行自动抓取。其他站点的公开可访问性也不自动构成持续商业采集授权。

1. TC-INV：打开民航局目录四页，核对65项名称；货运与集团入口单列，不补造客票。
2. TC-HOME：各独立客运域名导航、记录重定向和TLS状态、保存首页截图；不将HTTP 200或首页推广价算作实时报价。
3. TC-QUERY：使用公开查询表单或公开特价链接，选择城市建议、日期、单程1成人，提交后核对结果条件。
4. TC-QUOTE：核对至少一个具体航班号、两端时刻、结果日期、对应舱位价格和税费口径；人工审阅后才将quoteVerified标真。
5. TC-BARRIER：遇登录、点选验证、会话过期或TLS错误保存证据并停止；不登录、不绕过、不忽略TLS。
6. TC-QUALITY：检查共享/经停/跨日、会员限制、行李、售罄/Infinity；未验证最终支付总额。
7. TC-ADAPTER：脚本点击失败要与真实业务限制分开；修正弹窗、城市建议、异步日历、弹出结果标签页后重试。

已执行通用表单多轮重试、人工修正、公开推广入口补测。`submitted-result-needs-review`只表示脚本提交阶段完成；`results.json`人工复核才是最终结论。原始通用脚本中的`quoteVerified:false`保留，不用脚本阶段状态冒充核实结果。

未测：全部航线/日期、出票库存锁定、支付价、登录后查询、压力/并发、跨日持续运行、云服务器环境；13个集团条目的独立承运主体未验证。未发现航班/价格的站点不判定没有航班。
