## 确认的问题

### RETEST-01 复合记忆问题只回答第一项

优先级：P2。影响：用户一条消息查询多个已保存条件时，回答不完整，容易误以为其他事项已经丢失。

复现步骤：

1. 在独立对话中保存“旅行代号是青竹4726”和“同行人的名字是林舟”。姓名与代号均为本轮虚构测试数据。
2. 追加20条不同的显式旅行备忘。
3. 询问“本次测试旅行代号是什么？同行人叫什么？”

实际仅返回“当前对话保存的旅行代号是：青竹4726。”，漏答同行人。之后单独查询同行人仍返回林舟，说明该次遗漏不是事项整体遗失。再次组合查询同行人和第一项备忘，也仅命中其中一项。

预期：分别回答所有可确认事项，对缺失项单独说明。建议将单条 `matchingFact` 命中改为多项匹配与结构化汇总，避免规则提前返回。

### RETEST-02 修改指令尾语被写入记忆字段

优先级：P2。影响：字段值被操作说明污染，后续召回或参与规划时不再是干净的事实值。

输入“把本次测试旅行代号改成白鹭9361，其他不变。”，系统确认并在再次查询时返回“白鹭9361，其他不变”。“其他不变”被保存为代号的一部分。

预期代号仅为“白鹭9361”，其他字段保持原值。建议将修改对象、新值、约束说明分开解析；仅对明确的尾部操作指令做结构化处理，避免误删用户本来想保存的内容。

上述两项证据：[30轮账户记忆结果](account-memory.json)。原始首次观察另保留在 [初次记录](account-memory-initial.json)。模型直连检查与记忆规则响应分别报告，不能将这些规则记忆操作冒充30轮大模型对话。

### RETEST-03 执行管理统计区定义列表结构不合法

优先级：P2。axe规则：`definition-list`，工具影响级别：serious。

在已生成旅行方案的执行管理页运行WCAG 2A/2AA规则扫描，统计区 `dl` 被报告为包含不允许的 `div > small` 子结构。视觉显示正常，但不满足定义列表分组语义，可能影响辅助技术的读取。

预期：每组使用规范的 `dt` / `dd` 结构，将说明文字放入适当的 `dd`；或将不具有定义关系的统计卡片改为普通列表/容器。修正后重新扫描并人工检查读屏顺序。

证据：[无障碍扫描结果](accessibility.json)、[执行管理截图](screenshots/travel-execution-desktop.png)、[手机执行管理截图](screenshots/travel-execution-mobile.png)。

## 可改善部分

1. 航空结果仍等待约24秒。火车独立显示已经有效，但可继续改善单航司超时、缓存命中提示、已有报价先展示及剩余来源进度；不建议以虚构数据换速度。
2. 推荐理由需要关联旅行日期和到访时段。本次11月行程仍出现“郁金香与樱花季顶流”，上午到访的地点使用“夜游起点”作为理由。它们是已观察到的文案适配不足，不能据此认定所有推荐地点不适合游览。
3. 本次5个推荐地点仅1个被统计为具有地点关联资料；界面已明确标注未核验。可补充对应地点的直接官方来源，并校准通用文旅资料与具体地点的关联统计。

## 用例适配与误报排除

首轮接口结果为73通过、9未通过：8项旧用例没有包含服务端新增的派生字段 `tripDays=2`，整对象相等断言因此失败；另1项交通对话使用旧20秒请求超时，早于当前航空查询预算。更新共享夹具和请求等待范围后，仅复核这9项，全部通过，合并为82个不同用例通过。原始失败未删除，也没有修改业务代码使其通过。

手机与历史切换脚本曾使用过期的 `.conversation-feed` 定位器，并在历史恢复完成前继续点击导航。依据当前真实DOM改为 `.conversation-messages`，等待方案恢复后复核，手机菜单、新建对话隔离和历史恢复均通过。这两次脚本失败不列为网站缺陷。
