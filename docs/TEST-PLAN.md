# 测试计划

目标是验证行知公开站点的实际行为，并提供独立于应用实现的可重跑验收用例。应用仓库：[xingzhi-ai-planner](https://github.com/liangjie798/xingzhi-ai-planner)。

## 范围与方法

| 层次 | 范围 | 方法 |
| --- | --- | --- |
| 线上接口 | 非法 JSON、类型/日期/范围边界、模型与查价状态、六场景、多轮修改 | Playwright APIRequestContext；严格断言预期状态和业务结果 |
| 会话 | 创建、更新、读取、跨访客隔离、CSRF 拒绝 | 两个独立 Cookie 上下文；只操作测试自建记录 |
| 浏览器 | 用户/访客入口、工作区路由、历史切换与刷新、图文方案、下载、空输入 | Chrome/Chromium 真实页面；不模拟核心规划数据 |
| 响应式 | 七条页面路径，390×844 与1440×1000 | 根元素宽度断言及截图；不等同于所有设备覆盖 |
| 无障碍 | 登录、工作台、逐小时、设置 | axe-core WCAG 2.1 A/AA；严重/致命项阻断；人工键盘抽查 |
| 异常恢复 | 天气接口503、地理定位拒绝 | 浏览器拦截明确标记为模拟故障，其他数据保持真实 |
| 源码回归 | 原项目lint、Node测试、生产构建、Java测试、发布历史检查 | 单独克隆/本地源码运行；不复制业务源代码到此仓库 |

## 判定

- `passed`：该次执行满足本用例的验收断言。
- `failed`：实际结果违反断言；进一步检查后，只有真实产品问题进入缺陷清单。
- `skipped`：未执行，必须解释，不能算通过。
- 超时、上游波动和测试脚本错误必须与产品缺陷区分。脚本修正后保留最终有效运行结果。
- 已知缺陷仍保持失败断言，不使用 `test.fail()` 把产品问题转成绿色。
- 参数错误应返回可理解的4xx错误，不能崩溃成500。接口输出为空或降级时必须明确说明。

## 负载与数据

单worker执行，无并发压测。每个用例只发出有限请求；不批量注册、猜测管理员密码或修改真实用户。UI可创建临时访客对话，由隔离上下文限定。会话隔离测试在finally里删除其自建记录；普通页面加载自动产生的访客记录随会话失效，无用户业务记录被删除。

## 明确未覆盖

无真实普通用户和管理员测试凭据，因此线上注册后的持久登录、密码重置、管理员增删改及跨已注册账户隔离未做全链路；本地后端已有相关集成测试单独报告。未实施容量/压力测试、渗透扫描、支付/预约或第三方实际购票。无模型凭据时只验证明确降级，不把规则结果当作大模型通过。下载验证到文件字节、容器和Markdown内容；未声称完成Word/PDF的视觉排版验收。axe通过不代表完整无障碍认证。线上未公开部署SHA，不能把本地提交号视为已证明的线上版本。

## 可重跑

```sh
npm ci
npx playwright install chromium
npm test
npm run report
```

已有Google Chrome时可设置 `PW_CHANNEL=chrome`；测试目标由`BASE_URL`设置。变量用shell传入；`.env.example`仅提供说明，不自动加载。测试日期按运行时北京时间生成，避免硬编码旧日期。测试会产生失败退出码，完整结果仍写入`reports/execution.json`。

独立源码检查：设置`SOURCE_DIR`与Java21环境后运行 `npm run check:source`。不需把任何生产密钥提交到本仓库。
